# 公众号头像跳转组件

把头像显示在指定尺寸的方框中，使用原生 `mp-common-profile` 名片提供跳转。适合题头头像与文末署名。AI 根据用户提供的账号线索和已有登录取得真实名片，再读取其账号身份与头像。

## 需要的材料

先检查已有资料，缺项一次列出。

| 材料 | 获取方式 |
|---|---|
| 公众号名称、微信号或已发表文章链接 | 用户给出其中一种线索，AI 核对文章作者或账号搜索结果 |
| 可用的浏览器登录 | 用户在自己的公众号或编辑器中完成登录，AI 继续使用该会话 |
| 希望显示的头像 | 沿用目标账号当前头像，也可以由用户提供图片以便核对 |
| 已有原生名片或含名片的草稿 | 提供后直接提取对应组件，可省去重新插入 |
| 尺寸和位置 | 沿用用户要求或当前文章设计，脚本默认头像边长 120px |
| 头像下方提示文字 | 根据用途确定，默认“点击头像查看公众号” |

先使用现有资料完成账号定位和名片提取。缺少登录、工具访问或必要账号线索时，集中提示具体缺项，让用户补齐后继续。

源稿含多个不同公众号时，先确定目标账号。脚本支持 `--account-id` 选择已有名片，重复且资料一致的同账号名片会自动合并选择。

## 先由 AI 取得原生名片

进入浏览器前先读取当前环境可用的操作说明。环境提供 Ego lite 时，读取其当前 Skill 并执行 `ego-browser skill`，再按输出操作。

1. 已有原生名片时，从用户提供的文件或指定草稿中提取该账号的 `mp-common-profile` 组件。
2. 尚未有名片时，使用当前浏览器会话进入用户有权编辑的草稿。先查看当前 snapshot，定位原生公众号名片插入入口，再按名称或微信号搜索并核对目标账号。只有文章链接时，先从该文章确认账号名称，再继续操作。
3. 插入真实名片后，通过当前工具可用的编辑器或 DOM 读取能力取得该组件的 HTML，保存为本次工作目录中的 `account-card.html`。核对其中 `data-id`、`data-nickname` 和 `data-headimg`，随后调用下方脚本。用户提供的头像与卡片头像有差异时，先核对目标账号及最新头像。
4. 当前工具或账号状态使 AI 无法取得名片时，向用户说明卡在哪一步，并根据当前可见入口引导其完成必要操作。用户接手结束后，继续提取名片和生成组件。

135 官方文档提供了在公众号后台插入名片，再通过预览页或开发者工具取得卡片代码的做法。具体按钮位置以当前编辑器 snapshot 为准。[获取公众号卡片代码](https://www.135editor.com/books/chapter/1/489)

## 生成组件

使用 Python 3.10+，脚本只依赖标准库。将 AI 本次取得或用户已经提供的真实名片保存为 HTML 文件，输入与输出都使用本次工作目录。

```text
python scripts/render_avatar.py --card-html account-card.html --out avatar-component.html --size 120
```

可按需要加入以下参数。

```text
--account-id 目标名片中的真实data-id
--caption 点击头像，认识一下
--size 72
```

`--caption` 包含空格时按当前命令行规则加引号。`--size` 接受正整数，实际尺寸应适合正文可用宽度。

- 返回 `needs_input` 时，集中转述 `missing` 和 `issues`，补齐后重新运行。
- 返回 `rendered` 时，读取生成的 HTML，核对可见名称、头像与原生卡片字段。
- 脚本保留名片原始属性，头像点击层限定在指定头像框内。组件文件可插入已有文章相应位置。

## 在编辑器落地

用户要求实际排版时，沿用已确认的浏览器会话和当前操作说明。

1. 定位本次目标草稿和头像所在段落，保全现稿中的用户改动。
2. 将组件作为富文本插入相应位置，按当前编辑器支持的入口保留原生名片。
3. 保存并重新打开，检查头像尺寸、名称、名片身份和周围文字位置。
4. 同步到公众号草稿后再保存重开，检查原生名片是否保留。
5. 在手机微信预览中点击头像，确认进入预期公众号。检查点击区域局限于头像，周围正文仍可正常阅读和选择。

在编辑器只看到头像时，继续核对原生卡片。发生名片清除、身份变化或点击区域偏移时，保留当前稿，定位是粘贴、解析还是保存环节造成，再修正相关组件。

生成文件、编辑器保存和手机跳转分别按实际结果说明。对外发布沿用用户本次授权。

4. 修改后检查完整动作与返回，核对文字、图片和按钮边界，再检查目标编辑器中的保存结果。

本版已有600px浏览器操作／播放采集、320／375px布局检查，GIF记录与实际文件校验一致。
