# 实现与验证方法

组件由底层提示和答案层构成。答案层初始 `opacity="0"`，其中的透明矩形设置 `pointer-events="all"` 并覆盖组件范围。点击命中该矩形后，事件在答案层触发SMIL动画。`begin="click"` 对应当前目标元素的点击事件，使用局部结构即可定位。

答案层通过 `animate` 将 `opacity` 从0变为1，`fill="freeze"` 保留最终状态，`restart="never"` 将这次展示保持为一次触发。画布保持600×360，所以前后页面的占位高度一致。[W3C SVG动画规范](https://www.w3.org/TR/SVG11/animate.html)

答案层放一张与画布相同大小的底色矩形，再放文字或SVG图形，可以在显示时覆盖下面的提示。所有元素均在内联SVG内。当前代码依据规范独立编写，技术调研同时参考了MIT项目的透明点击热区说明。[调研配方](https://github.com/JamieJustTang/wechat-animating/blob/main/wechat-animating-authoring/references/smil-cookbook.md)

| 输入 | 要求或默认值 |
|---|---|
| `--answer` | 必填，最多五行，每行约14个全角字 |
| `--prompt` | 默认“点一下，查看答案”，最多三行 |
| `--color` | 默认 `#D97706`，六位十六进制值 |
| `--background` | 默认 `#FFF8EE`，六位十六进制值 |

换行符可用于手动断行。脚本按14em估算每行宽度，全角字按1em、普通ASCII按0.8em、较宽的W/M等按1em、窄标点及字母按0.4em估算，组合附加符号保持在前一个文字之后。每个原始字符都会进入对应的SVG文本节点，空格通过 `xml:space` 保留，HTML特殊字符会转义。具体系统字体的字形宽度继续通过浏览器边界与手机预览检查。

正文和“答案”标签统一采用36单位字号，行距44单位。600宽画布放在272px宽的正文区域时，实际文字字号为 `36×272÷600=16.32px`。答案最多五行，五个基线依次为120、164、208、252、296，在360高画布内保留上下间距。输入超出容量时会报告实际行数，再请使用者提供精简版本或确认拆分。

## 浏览器检查

根SVG的 `data-component` 为 `wechat-svg-click-reveal`，答案层带 `data-reveal-layer="answer"`，透明热区带 `data-reveal-trigger="tap"`。点击前后可读取答案层计算样式的opacity，预期先为0，点击后为1。读取根SVG的边界高度，前后应一致。

## 编辑器检查

若点击后仍显示提示，查看保存后的答案层、透明热区和 `animate` 属性。若高度或文字裁切变化，查看SVG `viewBox`、宽度、默认字体和编辑器包装层，再复测。手机微信和秀米本轮结果由实际测试补入，生成成功及浏览器响应可分别记录。

本组件的SVG使用内联形状、文字与SMIL属性，字体采用系统无衬线字体。点击事件由当前答案层处理。

## 2026-11-11 实际验证

Ego lite实际打开独立预览后，用鼠标点击透明热区。浏览器读取答案层opacity从0变为1，等到实际状态大于0.99再检查结果。组件显示宽640、高384，点击前后高度保持384。该尺寸来自测试页面中响应宽度的缩放，SVG的内部画布继续为600×360。已记录点击前后画面。秀米导入保存、微信草稿重开及手机触发仍待实际测试。
