# 信封拆信与收回

点击拆信，封口先翻开，信纸随后向上抽出。点击收信，信纸放回后封口合上。两段动作在一张固定画布内完成。

## 材料与生成

提供组件标题 `title`、信内标题 `letter_title` 与正文 `letter_body`。信内标题最多一行约12个全角字，正文最多三行，长信适合放入组件后的普通正文。

调整[配置示例](examples/config.json)。`accent`、`background` 使用六位HEX色值，`duration` 为两段动作合计时长，支持0.4～3秒。

```text
python <本Skill目录>/scripts/render.py --config <本次目录>/config.json --out <本次目录>/component.html --preview-out <本次目录>/preview.html
```

已有输出需要替换时加 `--overwrite`。片段和预览使用 `.html` 或 `.htm`，输入配置、Skill说明和生成器受保护。脚本保留输入文字并做XML转义，缺项、超长或非法数值会报告字段。

### 纸纹插画版本

插画版在原有拆信动作上增加真实纸纹与 AI 生成的信封口袋。标题、信内文字和按钮仍由原生文字排出，修改文案后重新生成即可。

`artwork` 为可选配置，不提供时沿用原矢量版本。提供时需同时填写以下两项，本地路径相对配置文件所在目录解析。

| 字段 | 提供什么 |
|---|---|
| `artwork.pocket` | 透明背景的信封前袋图片，横向约1.65∶1，正面平视、上沿浅V形，保留透明开口，不含信纸、封口或正文 |
| `artwork.paper` | 低对比折痕纸纹，不含文字，用于画布与信纸 |

两张图片均支持 PNG、JPEG、WebP，建议按实际展示尺寸准备素材。前袋需真实透明通道，推荐 PNG 或带透明的 WebP。生成器将图片嵌入 HTML，移动成品时无需搬运外部图片路径。原图保存在 `assets/`，便于替换和独立打包。图片也纳入输入保护，输出不能覆盖原图。

插画画布为600×800。信纸打开后上移250逻辑像素，最长三行正文应全部露出。替换前袋时请核对透明边距和V形开口，避免遮住信内文字。

打开[插画交互预览](examples/artwork-preview.html)，点击亮起的按钮。动画期间暂停两个按钮，完成后允许反向操作。重新生成插画版时采用[插画配置](examples/artwork-config.json)。

## 接入与检查

- 核对打开顺序为翻封口、抽信纸，收回顺序为放信纸、合封口。
- 信纸抽出后检查全部正文，连续拆收两轮。
- 初始灰色按钮、快速连点和重复同向点击应保持当前状态。
- 320、375px视口核对纸张、文字、信封和按钮边界，同篇双实例分别操作。
- 秀米保存重开后从阅读页重新拆收，再核对公众号与手机微信。

片段采用SVG与SMIL。事件ID独立生成，点击锚点位于 `g` 节点。秀米清理数据属性后，可用 `g[id^="envelope_"][id$="_forward"]` 和 `_reverse` 定位。`_paper` 组的纵向平移在原矢量版本为0与−190，插画版本为0与−250。`_flap` 组在打开后隐藏、收回时恢复。


阅读的参考笔记提示在秀米搜索“信封”获取模板，本包采用自行绘制的矢量信封、纸张与时序。需要在秀米参数面板修改原生模板时，可从该关键词寻找当前入口。[小红书参考案例](https://www.xiaohongshu.com/explore/6ad7601d000000001e03781b)

HTML 内嵌图片用于本地和仓库预览，导入秀米后还需确认图片经过平台上传并保留，再核对保存重开与手机效果。
