# 三题计分与结果

固定三题，每题2到3个选项，恰好一个正确答案。选对1分，选错0分，选完立即进入下一题。结果只计算当前页面的选择，重新开始清零。

## 先收齐文字与关系

需要用户给出当前组件的真实文字、正确关系或检查项目，并确认放在文章哪一段。缺项集中列出，保留用户已经确认的措辞。

| 字段 | 内容与范围 |
|---|---|
| `questions` | 恰好三题，每题含 question 和 choices |
| `question` | 最多两行，每行约16字 |
| `choices` | 每项含一行 label 与布尔 correct，每题恰好一个 true |
| `results` | 恰好四项，顺序对应0、1、2、3分，每项含 title、body |

所有组件均支持 `title`、`description`、`accent`、`background`。标题一行约16字，说明最多两行、每行约24字，颜色采用六位 HEX。中文按显示宽度检查，超长文字会给出实际行数，取得精简版本后继续。

## 生成本次组件

先替换 [输入示例](examples/config.json)，运行独立生成器。Python 3.10或更高版本，依赖标准库。

```text
python <本Skill目录>/scripts/render.py --config <工作目录>/config.json --out <工作目录>/component.html --preview-out <工作目录>/preview.html
```

输出 `component.html` 和可直接打开的 `preview.html`。已有输出需要本次明确替换时，增加 `--overwrite`。默认拒绝覆盖，输出路径与输入配置分开。脚本、素材和参考资料目录受到保护。

写入采用输出文件锁、先暂存全部文件再提交。覆盖失败时恢复已提交的旧文件，恢复遇到问题会报告保留的备份位置。

## 交互与鼠标检查

状态 q0-s0 开始，后续 q1-s0 等名称记录题序和已得分。answer-0、answer-1、answer-2 按选项序号作答。最后进入 result-0 到 result-3，restart 回到 q0-s0。示例正确序列为 answer-0、answer-1、answer-0。

1. 走完全部正确、全部错误和混合答案，核对得分及结果文案。
2. 结果页重新开始，确认当前分数清零。
3. 同篇放两个实例，分别操作，检查随机事件ID和状态互不影响。
4. 在320px、375px阅读宽度检查字级、按钮和画面边缘。

状态组带 `data-state`，按钮带 `data-action` 与 `data-target-state`。查找动作时先限定本组件实例，再定位当前可见状态。事件ID带每次生成的随机前缀。接收端清理数据标记时，可按保留的组ID和按钮文字重新定位。

## 品牌与本人素材

画布为600×840，普通文字保持SVG文字。奶油纸色、暖橙和黑线来自示例主题，可按本篇风格调整。

图层留有 `data-artwork-slot`，采用 `idea`、`studio`、`launch` 槽名及 `data-x/y/width/height` 位置尺寸。中央品牌器可在槽内换入当前授权的头像和插画。复用时先换为本人的素材，并保留状态组、事件ID与透明点击区域。

## 本地实现与交付验证

已实现可交互的本地SVG/SMIL预览，导出片段使用有限状态及事件动画。当前生成和结构检查结果以本次验收记录为准。

秀米导入后需保存并重新打开，逐项检查显示和完整动作。同步到公众号后，再保存重开，并在真实手机微信检查点击、返回和文字边缘。取得对应结果后更新这一项的实际验证范围。

用户完成扫码并明确说可以继续后，恢复同一个浏览器工作空间。最后交付实际草稿位置、组件所在段落、完成的检查与仍缺材料。

## 调研依据

本轮参考了懂点君的 SVG 选择答题与多选项统计得分案例。原案例讨论选项不同分值，本包采用三题单选、每题1分的固定规则。题目和结果为本包自编教学示例。[调研案例](https://www.xiaohongshu.com/explore/680f522300000000210010da)

## 品牌演示与GIF

[查看可操作演示](examples/brand-preview.html) · [查看GIF](examples/demo.gif) · [读取品牌样式与素材](examples/brand-style.json)

1. 先看GIF选择效果，再读取 `examples/brand-style.json` 和 `examples/brand-component.html`，确认本组件的画布、配色及素材。
2. 按本次任务采用使用者自己的头像、账号资料、正文与配图。直接修改本地品牌HTML模板和相邻素材即可复用单项包。原有生成器的参数能力以本Skill正文为准。
3. 文字保留原生编辑。图片放在对应动画组或状态组里，保留事件ID、SMIL时序与透明点击区。同篇放多个实例时，分别生成独立ID并同步事件引用。
4. 修改后检查完整动作与返回，核对文字、图片和按钮边界，再检查目标编辑器中的保存结果。

本版已有600px浏览器操作／播放采集、320／375px布局检查，GIF记录与实际文件校验一致。
