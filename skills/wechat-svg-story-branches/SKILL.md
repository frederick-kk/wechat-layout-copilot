# 多步分支故事

调研时查看多叉树答题的分支转场与多页选择演示。本包将节点、选项和去向写入JSON，生成连续选择与不同结局。[小红书参考案例](https://www.xiaohongshu.com/explore/68653bfc00000000120219bc)

读者先选择一条路，进入下一步，再选择后续方向。结局处可以回到起点，重走另一条路线。

## 准备材料

先取得完整路径关系。需要起点 `start`、3到12个节点，每个节点包含 `id`、`title`、`body`、`choices`。每个选项包含显示文字 `label` 与目标节点 `to`。空选项列表表示结局。

当前画布每个节点容纳两行标题、四行正文，以及最多三个按钮。需要至少两个带选项的节点，形成连续选择。每个节点都应从起点可到达，并存在通向某个结局的路径。

`id`以英文字母开头，仅用字母、数字、下划线，最多40位。目标 `to`引用已存在的节点ID。需要更长叙述时，把背景放在组件前后的普通正文。

## 生成

替换[输入示例](examples/config.json)，先检查每条路径的去向，再运行。

```text
python <本Skill目录>/scripts/render.py --config <本次目录>/config.json --out <本次目录>/component.html --preview-out <本次目录>/preview.html
```

`accent`、`background`可配文章主题。已有输出需要替换时，加 `--overwrite`。片段使用SVG与SMIL，导出内容没有JavaScript。各实例的事件ID独立，初始显示状态同时写入属性和内联样式。

## 检查

- 从起点走完每条分支，核对中间节点与结局对应。
- 每个结局点重新开始，尝试另一条路。
- 单次只显示一个节点，旧节点按钮随节点隐藏。
- 合并两个实例，检查选择与重新开始互不影响。
- 320、375像素宽度检查按钮、正文和画布边缘。
- 秀米保存重开后，按保留的组节点ID检查各条路径，再核对公众号和手机微信表现。

已完成脚本、图关系、输入与结构检查。2026-11-12使用Ego lite实际鼠标，在320、375像素宽度下，本地预览与秀米保存重开后的阅读页均通过四条路径及结局重新开始检查，页面无横向溢出。公众号同步及真实手机微信触摸待验证。可打开[组件预览](examples/preview.html)走一遍两步故事。
