# 从旧文章学习个人排版

本阶段产物是 `profile.json` 中的 `style`，用于后续每篇文章沿用。用户只需给旧稿和反馈，由AI完成提取与整理。

## 先取得能看的依据

优先使用用户自己的旧文章。已有一篇完整样本时先开始，遇到规则不清或差异明显再补看其他文章。

新公众号可以先提供参考文章。只有口述视觉偏好时，先做可看的小样，确认后将小样文件与反馈作为风格来源。

| 可用材料 | 能据此提取的内容 |
|---|---|
| 可正常打开的文章与截图 | 实际阅读节奏、移动端呈现和整体视觉 |
| 编辑器HTML或可读DOM | 颜色、字体、字号、段距、图片与组件属性 |
| 完整截图 | 层级、布局与视觉关系，测量值注明估计 |
| 纯正文 | 章节与段落组织，视觉参数留待画面补齐 |

记录来源URL或本地文件、实际读取部分和重要观察。页面访问受限时，说明具体缺口，接收用户补充的HTML、截图或粘贴正文继续。

## 提取这些规则

- **身份与题头**，公众号名称、头像、署名、阅读提示和原生名片的实际形式。
- **配色与背景**，主色、强调色、正文色、底色及背景图处理。
- **文字层级**，正文、章节标题、重点句、图注及引用之间的区别。
- **阅读节奏**，行高、段距、内容宽度、短段与列表的使用方式。
- **图文关系**，图片比例、图注、分隔与正文前后的留白。
- **交互位置**，题头、章节切换、案例揭晓、结尾行动入口各适合什么效果。

能读到CSS时记录实际数值。依据截图估计的参数保留“估计”的标记。用户主动更改的值按本次反馈写入。

将作者语气观察单独记录为可选参考。仅排版任务沿用用户提供的正文，语气规则在用户需要改写时使用。

## 把风格与组件接起来

对已选组件说明具体用途与位置。例如把拆信用于读者来信或个人寄语，把时间线用于真实阶段，把点击揭秘用于适合先提问再揭晓的短答案。

素材需求来自对应组件Skill。头像入口需要本人的真实原生名片，视差需要分层画面，图集需要明确图片顺序，数据图表需要实际数值。根据用户已给材料先完成可做的部分，缺项集中列出。

模板中的示例内容与演示素材在制作时替换为用户本人资料和本篇内容。复用事件ID、动画时序与点击区域时，按组件说明处理多个实例之间的引用。

## 小样与反馈

用用户的一段实际正文做可打开的小样，覆盖本次需要确认的题头、正文层级、配图和交互。附一张“段落—组件—用途”表，方便用户直接指出调整位置。

把确认后的规则写回同一份 `profile.json`，保留旧稿来源和用户明确调整的依据。不同账号分别保存自己的配置。
